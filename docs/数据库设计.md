## 三、🔴 计费的两个硬约束

### 3.1 原子扣减

```sql
UPDATE subscription
   SET quota_used = quota_used + 1
 WHERE id = :sid AND quota_used < quota_total
```

看 `rowcount`：1 = 成功，0 = 额度不足。

**绝不能写成两条语句**（先 `SELECT` 查，再 `UPDATE` 写）：
并发下两个请求都读到 `quota_used=4`（总额 5），都判定「还有额度」，
都写回 6 → **超扣**。

### 3.2 账实相符恒等式

```
COUNT(usage WHERE tenant_id=A AND degraded=false) == subscription(A).quota_used
```

两边对不上是计费系统最典型的 bug（多扣了 / 扣了没记账）。
`tests/test_billing.py::test_usage_count_equals_quota_used` 盯着它。

**被额度拒绝的请求不留流水** —— 否则流水数会多于 `quota_used`。

## 四、租户隔离的实现

### 4.1 第一层：显式 `scoped()`

```python
scoped(Kb, tenant_id)              # → Kb.query.filter_by(tenant_id=...)
scoped(Kb, None)                   # → 抛异常（不过滤 = 全库可见，最危险的默认）
```

### 4.2 第二层：ORM 自动注入

```python
@event.listens_for(db.session, 'do_orm_execute')
def _auto_filter_tenant(state):
    if state.is_column_load or current_tenant_id.get() is None \
            or is_platform_admin():
        return
    tenant_id = current_tenant_id.get()
    # Tenant 单独处理（主键是 id，没有 tenant_id 列）
    state.statement = state.statement.options(_tenant_self_filter(tenant_id))
    for model in TENANT_SCOPED_MODELS:
        state.statement = state.statement.options(_tenant_filter(model))
```

**跳过过滤的三种情况**（都是刻意的）：

| 情况 | 为什么跳过 |
|---|---|
| `is_column_load`（懒加载续查） | 否则会重复加条件导致 `WHERE` 出错 |
| 无租户上下文 | CLI / 建表 / 测试造数据需要能跨租户 |
| 平台管理员 | 它的职责就是跨租户 |

### 4.3 🔴 两层会互相掩护

两道防线同时在效时，**打坏一层测试不会红**（另一层兜住了）。
所以有专门一组「关掉另一道、单独验这一道」的测试：

```python
reset_tenant_context()                    # 关掉第二道
assert len(scoped(Kb, a.id).all()) == 1   # 第一道必须自己能隔离

set_tenant_context(a.id)                  # 关掉第一道
assert len(Kb.query.all()) == 1           # 第二道也必须能
```

## 六、SQLite 并发设置

```python
cursor.execute('PRAGMA journal_mode=WAL')      # 读写不互斥
cursor.execute('PRAGMA busy_timeout=5000')     # 第二请求等待而非立刻失败
```

🔴 挂在 SQLAlchemy 的 `connect` 事件上，**每条新连接都要设**。
只在启动时设一次不够 —— 连接池新建的连接不带，遇并发写立刻 `database is locked`。
（实测 2/6 概率失败，不是理论推测。）

## 七、已知不足

| 项 | 说明 |
|---|---|
| **没有 Alembic** | 用 `db.create_all()`，改表结构要手工迁移。生产不可接受 |
| **没有计费周期字段** | `quota_used` 只增不减，无法按月归零。缺 `period_start` |
| **`document` 无 group_id** | 「按文档整体删除」只能按 `(kb_id, title)`，同名文档会一起删 |
| **无软删除** | 删了就没了 |
| **无审计日志表** | 谁在什么时候改了谁的权限，没有留痕 |
| **PostgreSQL 未验证** | 代码里只用了 SQLite 特化的 PRAGMA，换库要改 `apply_sqlite_pragmas` |
| **`usage.question` 可能包含敏感信息** | 明文存问题文本，没做脱敏 |
