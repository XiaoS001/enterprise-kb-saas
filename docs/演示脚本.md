## 四、引用校验的有效性

来源：`python demo_citation.py`

```
① 引用链路实测：上传 → 问 → 答 + 引用 → 解析回文档
上传：HTTP 201 · 切成 4 段
    id=1 #0 数据库连接池配置指南。
    id=2 #1 连接池的大小应该根据 CPU 核数乘以 2 再加磁盘数来估算。
    id=3 #2 慢查询排查步骤：先看 EXPLAIN 输出，再看索引命中率。
    id=4 #3 缓存穿透的常见解法是布隆过滤器和空值缓存。

提问：连接池大小怎么估算  → HTTP 200 · 命中 1 段
引用（references）：
    doc=2 《运维手册》第 1 段

② 引用校验：故意引用一个不存在的 doc_id
答案引用 [doc:99999]，实际证据 id=['2']
  ok                = False
  citations         = ['99999']
  invalid_citations = ['99999']
  → 🔴 引用校验拦住了编造

答案引用真实存在的 [doc:2]：ok = True

有证据但答案零引用：ok = False  reason = 有证据但未引用
```

### 这段的目的是证明「校验不是摆设」

| 场景 | `ok` | 说明 |
|---|---|---|
| 引用真实存在的 doc | `True` | 正常放行 |
| **引用不存在的 doc** | **`False`** | 🔴 编造的引用被拦住 |
| **有证据但零引用** | **`False`** | 🔴 不引用就免检是个洞，堵上了 |
| 答案明确说「查不到」 | `True` | 唯一合法豁免（只认具体措辞） |

## 七、演示时可能被问到的问题

**Q：没有 API key 也能演示？**
A：能，但只到「检索 + 引用」这一步，答案是空的。这反而是个亮点 ——
可以现场展示**降级时接口不 500、且不扣额度**。

**Q：为什么引用要精确到「第几段」而不是只给文档名？**
A：只给文档名等于说「答案在某份文档里，你自己找」。精确到段才能直接核对原文。

**Q：BM25 而不是向量检索？**
A：向量要联网下载 90MB 模型，首次运行会失败。BM25 零依赖，
且对「企业内部文档」这种术语密集场景够用。向量路径保留了代码但默认关。

**Q：多租户怎么保证不串数据？**
A：两层防线 + 一组「关掉另一道单独验这一道」的测试。
详见 README 4.1。
